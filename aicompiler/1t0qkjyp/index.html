01 编译器基础概念

编译器和解释器啥区别？AOT和JIT啥区别？Pass和IR又是什么？

编译器 和 解释器 区别

编译器compiler ：在程序运行之前，把你的整本源码（如 C/C++）一次性全部翻译成计算机能听懂的机器码（比如 .exe 文件） 解释器interpreter ： 程序运行的时候，他站在旁边读一行代码，就现场翻译一行，并让计算机执行一行（如 Python/JavaScript 默认模式）

JIT 和 AOT 编译方式

程序主要有两种运行方式：

  • 静态编译：程序在执行前全部被编译为机器码，称为AOT（Ahead of time），即“提前编译”；
  • 动态解释：程序边编译边运行，通常将这种类型成为JIT（Just in time），即“即时编译”；

提示

实际上，AOT 和 JIT 都是“编译器”（Compiler），而解释器（Interpreter）是与它们完全平行的另一种执行机制.

  1. AOT 和 JIT 都是编译器，区别只在于“编译的时机”
  • AOT（Ahead-Of-Time，预先编译）： 属于运行前编译。在程序提交或打包时，就把代码翻译成机器码存到磁盘里（比如生成 .exe 或 .so 文件）
  • JIT（Just-In-Time，即时编译）： 属于运行中编译。它也会生成机器码，只是它是在程序正在跑的时候，把高频执行的代码在内存里动态编译成机器码。 两者都在做“编译”这件事情（将高层代码/字节码转为机器码），只是一个在运行前（磁盘），一个在运行中（内存）。
  1. 解释器（Interpreter）与它们有什么不同？ 解释器的核心特点是：完全不生成机器码。
  • 解释器： 读一行源码/字节码，自己去理解并执行这一行的逻辑。如果一段循环代码执行了 10,000 次，解释器就会把这几行代码逐字“翻译+执行” 10,000 次。
  • JIT 编译器： 当发现这段循环代码执行了 10,000 次时，它会立刻把这段代码编译成机器码保存在内存里。第 10,001 次执行时，CPU 就可以直接跑机器码，速度大幅提升。
  1. 为什么大家容易把 JIT 和解释器混为一谈？ 因为在实际的现代编程语言运行环境（如 Java JVM、JavaScript V8 引擎、PyTorch）中，解释器和 JIT 编译器通常是“搭档合作”的：
  • 刚启动时： 使用解释器执行。优点是启动零等待，代码拿过来就能跑。
  • 运行一段时间后： JIT 编译器在后台默默观察，找出那些被频繁调用的“热点代码”。
  • 动态接管： JIT 编译器把热点代码偷偷编译成高性能机器码，替换掉解释器的逐行执行。 这种“解释器 + JIT 编译器”结合的混合模式，兼顾了启动速度和运行效率。

Pass，IR

IR（Intermediate Representation，中间表示） 编译器先统一把各种源码翻译成某种标准的中间状态（IR草稿），然后再把 IR 翻译成不同芯片的机器码。

Pass : 对源程序的一次完整扫描或处理 当源代码变成了 IR 草稿后，它需要通过（Pass）一道道流水线工序，每一道工序就叫做一个 Pass。 每一个 Pass 只干一件事： 死代码消除 Pass： 发现你写了一段永远不会执行的 if(false)，直接删掉。 常量折叠 Pass： 发现你写了 a = 1 + 2，直接帮你算好改成 a = 3，省去计算时间。 循环展开 Pass： 优化循环结构的执行效率。

03 GCC编译过程

GCC（GNU Compiler Collection）

.s 是汇编程序 预处理指令：gcc -E hello.c -o hello.i -o是声明文件名 编译指令：gcc -S hello.i -o hello.s 汇编指令：gcc -c hello.s -o hello.o

优点：

  1. 支持 JAVA/ADA/FORTRAN
  2. GCC 支持更多平台
  3. GCC 更流行，广泛使用，支持完备
  4. GCC 基于 C，不需要 C++ 编译器即可编译

缺点：

  1. GCC 代码耦合度高，很难独立，如集成到专用 IDE 上，模块化方式来调用 GCC 难；
  2. GCC 被构建成单一静态编译器，使得难以被作为 API 并集成到其他工具中；
  3. 从1987年发展到2022年35年，越是后期的版本，代码质量越差；
  4. gcc大约有1500万行代码，是现存最大的自由程序之一；

04 LLVM设计架构

LLVM : Low Level Virtual Machine （这个名字已经不符合LLVM现在的定义了） 现在LLVM项目已经发展为一个巨大的编译器相关的工具集合

提示

注意Clang 。有时候会同时提到GCC与Clang。 其实Clang只是作为LLVM编译体系里的前端，特别是使用C/C++/ObjC的时候，它都会使用Clang的前端，然后附带LLVM的优化器、后端。

LLVM IR详解

前端阶段（Front-End）：源码 →\rightarrow→ AST 中端优化流水线（Pass）：AST →\rightarrow→ 优化后的 LLVM IR 硬件指令转换阶段：LLVM IR →\rightarrow→ DAG 在 Pass 的末期，为了将代码翻译给具体的 CPU 芯片，LLVM 会把通用的 LLVM IR 转换为 DAG。DAG 可以把抽象逻辑映射到具体的芯片指令上。 后端生成阶段（Back-End）：DAG →\rightarrow→ Machine Code

LLVM IR基本语法

  1. 注释以;开头
  2. 全局表示以@开头，局部变量以%开头
  3. alloca在函数栈帧中分配内存
  4. i32 32位 4个字节的意思
  5. align 字节对齐
  6. store写入
  7. load读取

LLVM IR 作为一种编译器 IR，它的两个基本原则指导着核心库的开发

  • SSA 表示，代码组织为三地址指令序列，无限寄存器。
  • 整个程序的 IR 存储到磁盘让链接时优化易于实现。

LLVM IR 采用，具有两个重要特征：

  • 代码组织为三地址指令序列
  • 寄存器数量无限制

当程序中的每个变量都有且只有一个赋值语句时，称一个程序是 SSA 形式的。LLVM IR 中，每个变量都在使用前都必须先定义，且每个变量只能被赋值一次。以 1 * 2 + 3 为例：

1   %0 = mul i32 1, 2
2   %0 = add i32 %0, 3
3   ret i32 %0

SSA形式：
1   %0 = mul i32 1, 2
2   %1 = add i32 %0, 3
3   ret i32 %1

每个值只有单一赋值定义了它。每次使用一个值，可以立刻向后追溯到给出其定义的唯一的指令。极大简化优化，因为SSA形式建立了平凡的use-def链，也就是一个值从使用到定义的列表。

LLVM IR基本语法

  • LLVM IR 是类似于精简指令集（RISC）的底层虚拟指令集；
  • 和真实精简指令集一样，支持简单指令的线性序列，例如添加、相减、比较和分支；
  • 指令都是三地址形式，它们接受一定数量的输入然后在不同的寄存器中存储计算结果；
  • 与大多数精简指令集不同，LLVM 使用强类型的简单类型系统，并剥离了机器差异；
  • LLVM IR 不使用固定的命名寄存器，它使用以 % 字符命名的临时寄存器；

每个三地址码指令，都可以被分解为一个四元组（4-tuple）的形式：（运算符，操作数1，操作数2，结果），由于每个陈述都包含了三个变量，即每条指令最多有三个操作数，所以它被称为三地址码。

指令类型指令形式四元组表示
赋值指令z = x op y ( z = x + y )( op , x , y , z )

LLVM IR 表示形式 LLVM IR 具有三种表示形式，这三种中间格式是完全等价的：

  • 在内存中的编译中间语言（无法通过文件的形式得到的指令类等）
  • 在硬盘上存储的二进制中间语言（格式为 .bc）
  • 人类可读的代码语言（格式为 .ll）

LLVM IR 示例：

1   ; Function Attrs: noinline nounwind optnone ssp uwtable
2   define void @test(i32, i32) #2 { ; 有个全局函数@test (a,b)
3     %3 = alloca i32, align 4 ; 局部变量 c
4     %4 = alloca i32, align 4 ; 局部变量 d
5     %5 = alloca i32, align 4 ; 局部变量 e
6     store i32 %0, i32* %3, align 4 ; %0 赋值给%3 c = a
7     store i32 %1, i32* %4, align 4 ; %1 赋值给%4 d = b
8     %6 = load i32, i32* %3, align 4 ; 读取%3,赋值给%6 就是函数参数a
9     %7 = load i32, i32* %4, align 4 ; 读取%4,赋值给%7 就是函数参数b
10    %8 = mul nsw i32 %6, %7 ; a * b
11    %9 = add nsw i32 %8, 100 ; a * b + 100
12    store i32 %9, i32* %5, align 4 ; 参数 %9 赋值给 %5 e ===> 就是转换前函数写的int c变量
13    ret void
14  }

Z LLVM IR 内存模型

Module (模块)
  └── Function (函数)
       └── BasicBlock (基本块)
            └── Instruction (指令)
  • Module（编译单元 / 模块）：
    • 作用： 对应源文件层级（比如一个 .c 文件编译出的全部内容）。
    • 包含： 全局变量、函数列表、目标架构信息等。它是整个编译流水线的最高容器。
  • Function（函数）：
    • 作用： 对应代码中的一个具体函数（如 int main()）。
    • 包含： 函数参数（Argument）和一系列基本块（BasicBlock）。
  • BasicBlock（基本块）：
    • 作用： 控制流图（CFG）中的节点。
    • 核心规则： 单入口、单出口。代码从头部第一条指令进入，顺序执行，最后一条指令必须是“终结指令”（Terminator Instruction，如 ret 返回、br 跳转）。基本块内部不允许发生任何条件跳转。
  • Instruction（指令）：
    • 作用： 最小的计算单元（如 add 加法、load 读取、store 写入）。

LLVM IR内存模型最重要概念：Value，Use，User

  • Value（被使用者 / 产出者）： 在 LLVM 中，“一切皆 Value”。任何可以计算出结果、或者能被其他人引用的东西都是 Value（包括指令 Instruction、函数参数 Argument、常量 Constant，甚至函数 Function 本身）。
  • User（使用者）： 继承自 Value。指需要消耗其他 Value 作为输入操作数的对象。例如加法指令 %3 = add i32 %1, %2 就是一个 User，它使用了 %1和 %2。 (注：User 继承自 Value 是因为“指令本身计算出的结果”又可以作为下一条指令的 Value，这种设计极具美感)
  • Use（联系桥梁）： 记录 User 与 Value 之间一对一的使用关系，就像连接生产者和消费者的“指针纽带”。

在传统的语法树中，要想知道“某个变量在后面被谁用到了”，必须遍历整棵树，效率极低。而基于 Value/User/Use 设计，LLVM 在内存中天然双向绑定了代码依赖

  • use-def 链（从使用处找定义处）：
    • 场景： 拿到一条指令，快速问：“我的输入参数是在哪里算出来的？”
    • 应用： 常量折叠。如果发现一条加法指令的两个输入参数都是已知常量（例如 add 1, 2），直接把它们替换成 3。
  • def-use 链（从定义处找所有使用处）：
    • 场景： 拿到一个变量/指令结果，快速问：“后面有哪几条指令用到了我算出的这个值？”
    • 应用： 死代码消除（DCE）。如果你定义了一个变量 %x，但查询它的 def-use 链发现没有任何人使用它（使用者列表为空），编译器就可以直接把算 %x 的那条指令安全删掉。

LLVM 前端 和 优化层

LLVM 前端： 词法分析，语法分析，语义分析

LLVM 优化层： 优化通常由分析Pass和转换Pass组成 分析Pass：负责发掘性质和优化机会 转换Pass：生成必需的数据结构，后续为后者所用（这是真正处理的Pass）

Pass 依赖：显式依赖，隐式依赖

Pass API： 选择合适粒度的Pass的子类：ModulePass，FunctionPass，BasicBlockPass

LLVM 后端

后端由一套分析和转换Pass组成，它们的任务是代码生成，即将LLVM IR变换为目标代码（或者汇编）

图中白色的Pass为非必需Pass,灰色的为必需Pass

1、Instruction Selection 指令选择

  • 内存中 LLVM IR 变换为目标特定 SelectionDAG 节点；
  • 每个DAG能够表示单一基本块的计算；
  • 节点表示指令，而边编码了指令间的数据流依赖；
  • 让LLVM代码生成程序库能够运用基于树的模式匹配指令选择算法。 2、Instruction Scheduling 指令调度
  • 第1次指令调度（Instruction Scheduling），也称为前寄存器分配（RA）调度；
  • 对指令排序，同时尝试发现尽可能多的指令层次的并行；
  • 然后指令被变换为MachineInstr三地址表示。 3、Register Allocation 寄存器分配
  • LLVMIR 两个重要特性之一：LLVM IR 寄存器集是无限；
  • 这个性质一直保持着，直到寄存器分配（Register Allocation）；
  • 寄存器分配将无限的虚拟寄存器引用转换为有限的目标特定的寄存器集；
  • 寄存器不够时挤出（spill）到内存。 4、Instruction Scheduling 指令调度
  • 第2次指令调度，也称为后寄存器分配（RA）调度；
  • 此时可获得真实的寄存器信息，某些类型寄存器存在延迟，它们可被用来改进指令顺序。 5、Code Emission 代码输出
  • 代码输出阶段将指令从 MachineInstr 表示变换为 MCInst 实例；
  • 新的表示更适合汇编器和链接器，可以输出汇编代码或者输出二进制块特定目标代码格式。

流水线设计总结：

阶段输入数据结构输出数据结构核心解决问题
1. 指令选择LLVM IRSelectionDAG抽象逻辑 →\rightarrow→ 硬件具体指令匹配
2. 前期调度SelectionDAGMachineInstr (虚拟寄存器)铺平图结构，最大化指令并行 (ILP)
3. 寄存器分配MachineInstr (虚拟寄存器)MachineInstr (物理寄存器)无限虚拟寄存器 →\rightarrow→ 有限物理寄存器
4. 后期调度MachineInstr (物理寄存器)MachineInstr (优化排布)消除内存溢出代码和物理寄存器冲突引起的延迟
5. 代码输出MachineInstrMCInst / 二进制 / 汇编生成最终交由硬件运行的文件
