基础概念

约 699 字大约 2 分钟

2026-08-17

算子与kernel 算子(Operator / Op) 是一个具体的数学运算 kernel(核函数) 是在具体硬件上的实现 算子定义了“做什么” (What to do)，而 Kernel 定义了“怎么做” (How to do it) AI编译器的核心工作之一，就是完成从 Operator (图层) 到 Kernel (代码层) 的“降级” (Lowering) 和优化。 过程解析：

  1. 前端 (Frontend)： 接收用户定义的模型，生成计算图（Graph）。图中的节点就是算子。
  2. 中间表示 (IR) 优化： 编译器会对算子进行优化，比如：
    • 算子融合 (Operator Fusion)： 将 Conv2d + Bias + ReLU 三个算子合并成一个大算子。
    • 代数化简： 消除无用的计算。
  3. 后端 (Backend) / 代码生成 (Codegen)：
    • 编译器根据硬件特性，为优化后的算子（或融合算子）生成具体的 Kernel 代码。
    • 这一步可能使用手写的高性能库（如 cuDNN），也可以使用自动调优机制（如 TVM AutoScheduler, OpenAI Triton）自动生成 Kernel。

LLVM 是一个模块化、可重用的编译器和工具链技术的集合 MLIR 是多级中间表示 CUDA 统一计算设备架构，是由 NVIDIA 开发的并行计算平台和编程模型 CUDA源代码本质上是C++代码，和C++都在“高级语言”层级。CUDA 并不是一门全新的语言，它是对 C++ 进行了扩展。 标准 C++只能跑在 CPU 上。 CUDA C++ 既包含跑在 CPU 上的代码（Host Code），也包含跑在 GPU 上的代码（Device Code）。

线程索引（Thread Index）是并行计算（如 CUDA 或 OpenCL）中的一个“身份标识”。

循环不变代码运动（LICM） LICM (Loop-Invariant Code Motion) 是一种经典的编译器优化技术：如果循环体内的某项运算结果在整个循环过程中完全不会改变，那么这项运算就不应该待在循环里。编译器会自动把它“提”到循环开始之前只执行一次。

并行循环不变代码移动 (Parallel LICM) 当把代码放到 GPU 这种并行加速器上时，情况变得更复杂了。并行优化不仅要考虑减少计算量，还要考虑访存开销和寄存器压力。 在并行环境下（如 CUDA），数千个线程同时运行：

  • 计算冗余： 如果每个线程都在自己的寄存器里算一遍 base_salary * tax_rate，虽然是并行的，但依然浪费了计算资源。
  • 访存优化： 这种优化往往配合常量内存（Constant Memory）或共享内存使用。

并行循环不变代码移动：在普通的循环里，它是把代码移出 for；在并行计算里，它是把代码移出 “内核（Kernel）” 这个大循环。
