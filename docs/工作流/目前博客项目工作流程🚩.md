### 博客文章 vs 笔记 vs 普通页面

- **博客文章**：`docs/` 下除 `notes/`、`preview/`、`.vuepress/` 外的 `.md`，进入 `/blog/` 列表、分类、标签、归档。由 frontmatter 的 `categories` / `tags` / `title` / `permalink` 控制。
- **笔记**：`docs/notes/` 下，由 `notes.ts` 定义成侧边栏导航，不进博客列表。
- **草稿**：frontmatter 加 `draft: true`，不进博客列表（页面本身仍可通过 URL 访问）。

## 三、内容编写流程

1. 在 Obsidian 主库写文章。
2. 两种方式进博客：
   - **正文同步**：在 `scripts/sync.config.json` 加映射，运行 `npm run sync:posts`（单向正文同步，博客端改 frontmatter 是安全的，改正文会被主库覆盖）。
   - **手动复制**：直接复制进 `docs/` 对应目录，之后博客端自由修改。
3. 补/改 frontmatter：`title`、`categories`、`tags`、`createTime`、`permalink`（可选）。

## 四、本地命令（Windows cmd / PowerShell）

```bash
npm run docs:dev        # 本地开发服务器（localhost 实时刷新）
npm run docs:dev-clean  # 清缓存启动开发服务器
npm run docs:build      # 构建生产（输出到 docs/.vuepress/dist）
npm run docs:preview    # 本地预览构建产物
npm run sync:posts      # 同步 Obsidian 主库文章到博客
npm run vp-update       # 升级 vuepress / theme
```

## 五、发布流程

`push` 到 `main` 分支即自动发布，无需手动构建：

1. 本地确认无误后提交：
   ```bash unfold
   git add <文件>
   git commit -m "add: xxx"
   git push origin main
   ```
2. `.github/workflows/docs.yml` 自动触发：
   - checkout（拉全量提交记录）→ 装 Node 22 → `npm ci` → `npm run docs:build` → 部署 `docs/.vuepress/dist` 到 `gh-pages` 分支。
3. GitHub Pages 读 `gh-pages` 分支，站点更新。
4. 也可在 GitHub Actions 页面手动 `workflow_dispatch` 触发。

## 六、注意事项

- **`base` 为 `/`**：仓库是 user site（`Easton119.github.io`），根路径部署。踩坑记录里「加 `/<repo-name>/`」是旧 `vuepress-Blog` project 仓库的做法，已过时。
- **Workflow 权限**：Settings → Actions → General → Workflow Permissions 需设为 **Read and Write**。
- **Pages 源**：Settings → Pages 选 **Deploy from a branch**，分支 `gh-pages`。
- **分类由 frontmatter 决定**，与文件所在文件夹无关。
